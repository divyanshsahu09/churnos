## The Problem Nobody Solves in Tutorial Projects

A churn probability alone is useless to a business:

| Question a manager actually asks | Tutorial project | **Churn Rescue OS** |
|---|---|---|
| Who will churn? | ✅ Probability | ✅ Probability |
| **Why** will *this* customer churn? | ❌ | ✅ Reason code per customer |
| **When** — this month or in 6 months? | ❌ | ✅ Risk window (Critical / Near / Distant) |
| Should we give everyone a discount? | ❌ (loses money) | ✅ No — segment first |
| Who will stay *anyway* (don't waste discount)? | ❌ | ✅ "Sure Things" segment |
| Who will churn *because* we annoyed them with an offer? | ❌ | ✅ "Sleeping Dogs" segment |
| How much money is at risk, in ₹/$? | ❌ | ✅ CLV-at-Risk per customer |
| If we spend $X on retention, do we make it back? | ❌ | ✅ **Power BI What-If ROI Simulator** |

That last table *is* your interview story.

## The 4-Segment Rescue Framework (Uplift Thinking)

```
                    High churn risk
                         │
        LOST CAUSES      │      PERSUADABLES  ★
        (will leave      │      (will stay IF
         anyway —        │       you act — spend
         don't spend)    │       your budget HERE)
    ─────────────────────┼─────────────────────
        SLEEPING DOGS    │      SURE THINGS
        (happy until     │      (will stay anyway —
         you poke them — │       don't waste a
         LEAVE ALONE)    │       discount on them)
                         │
                    Low churn risk
              Low loyalty / price-sensitive  →  High
```

Segmentation uses churn probability × price-sensitivity × loyalty proxy (tenure + contract + support). This is a *proxy uplift model* — be honest about that in interviews (see `docs/INTERVIEW_NOTES.md`). Real uplift needs A/B test data; this shows you understand the concept, which 95% of candidates don't.

## Quickstart (Windows / Linux)

```bash
python -m venv .venv
.venv\Scripts\activate        # Windows  |  source .venv/bin/activate on Linux/Mac
pip install -r requirements.txt
python src/train.py
python src/predict_and_segment.py
# → outputs/powerbi_customers.csv is ready for Power BI
```

Then open `powerbi/BUILD_GUIDE.md` and build the dashboard (Page 1: Executive, Page 2: Rescue List, Page 3: ROI Simulator with What-If parameter).

## Dashboard — 3 Pages

**Page 1 · Executive Churn Command Centre**
KPI cards: Customers, Churn Rate, Revenue at Risk, Persuadables count • Churn by Contract / Internet / Payment (bar) • Risk donut • Tenure vs Churn trend

**Page 2 · Rescue List (the page no tutorial has)**
Table of Persuadables sorted by `Net_Save_Value` desc, with Reason, Risk Window, Recommended Action, Offer Cost, CLV at Risk. Slicers: Segment, Contract, Risk Window. *This is an action list a retention team uses on Monday morning.*

**Page 3 · Retention ROI Simulator ★**
What-If parameter `DiscountPct` (0–30%) + slicers for Assumed Save Rate → DAX calculates: Cost to Intervene, Revenue Saved, **Net ROI, ROI %**. Move the slider, the business case changes live. Interviewers *love* this demo.

## Model

- Features: one-hot contract/internet/payment/services, tenure groups, charges, senior/partner/dependents
- Models compared: Logistic Regression vs Random Forest (held-out test, stratified)
- Per-customer explanations: rule-based reason codes derived from the customer's own top risk features (transparent, explainable to a non-technical manager — a deliberate choice over black-box-only SHAP in the CSV)
- See `outputs/metrics.json` for the real numbers from *your* run — use those exact numbers on your resume, not the ones in any blog.

## Honest Limitations (say these in the interview — it builds trust)

1. Segmentation is a *proxy* for uplift, not a causal uplift model — true uplift needs randomised offer/no-offer experiment data.
2. CLV is estimated (MonthlyCharges × expected remaining months by contract), not a full survival/CLV model.
3. Telco data is a public benchmark; the framework transfers to SaaS / D2C / banking with their event data.

Naming limitations unprompted is what separates a standout candidate from a tutorial copy.
